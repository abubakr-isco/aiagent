## Что НЕ проверено

* **Подключение к реальному терминалу MT5** (Windows) и мост на реальном терминале.
* Поведение конкретного брокера: имена символов, режимы заполнения, stops level, перезапись
  комментариев, расчёт `order_calc_profit` для кроссов, торговые сессии и свопы.
* Бэктест на реальной истории брокера и длительное forward-тестирование на демо.
* `docker compose` (Docker недоступен в среде разработки).
* Strategy Tester MT5 не используется: стратегия написана на Python, а не как советник на MQL5.

## Как запускать

```bash
source .venv/bin/activate
pip install -r requirements-dev.txt

# только ядро (без БД):
python -m pytest tests/engine -q

# всё, нужен PostgreSQL. Встроенный вариант без установки сервера:
python - <<'PY'
import pgserver
srv = pgserver.get_server("./.pgdata", cleanup_mode=None)
srv.psql("CREATE DATABASE trading;")
print(srv.get_uri())
PY
export DATABASE_URL="postgresql://postgres:@/trading?host=<путь из get_uri>"
python -m pytest -q

cd frontend && npm run typecheck && npm run build
```

## Порядок проверки на реальном демо-счёте (этапы 5 и 8)

1. Шлюз `mt5` или `remote`, режим ANALYSIS, 1–2 дня: снимки по всем символам, нет ошибок связи,
   спреды и ATR правдоподобны, тип счёта DEMO.
2. Выгрузите историю M15 за 2–3 года по каждому символу (*Сервис → История котировок → Экспорт*) в
   `data/`, запустите walk-forward с реальным спредом и комиссией брокера.
3. Режим DEMO, Start. Минимум 4–8 недель forward-теста. Еженедельно: *Trade history → Demo* (метрики
   по символам), калибровка AI (`/api/ai/quality/`), `System logs` с уровнем «warnings and errors».
4. Сценарии сбоев на демо: выключить интернет на терминале (ожидается блок и переподключение со
   сверкой), перезапустить `run_agent` с открытой позицией (подхват без дублей), закрыть позицию
   вручную в терминале (сделка закрывается в журнале), Emergency stop.
